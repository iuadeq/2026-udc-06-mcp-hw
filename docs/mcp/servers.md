# MCP-сервери проєкту (Task A)

**Хост, у якому налаштовано:** Claude Code (CLI)
**Файл конфігурації:** `.mcp.json` (корінь репозиторію)

---

## Сервер 1 — filesystem

| | |
|---|---|
| **Навіщо** | Дає агенту можливість читати файли проєкту — зокрема `app/data/catalog.json` для перевірки даних каталогу та вихідний код для навігації |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @anthropic-ai/mcp-filesystem@latest /Users/iuade0tr/IdeaProjects/2026-udc-06-mcp-hw` |
| **Область доступу (scope)** | Обмежено каталогом цього репозиторію (`/Users/iuade0tr/IdeaProjects/2026-udc-06-mcp-hw`). Не домашня тека і не `/` — сервер бачить лише файли проєкту. Цього достатньо для всіх задач домашки, а ширший доступ створював би непотрібний ризик |
| **Секрети** | Немає — сервер не потребує токенів |
| **Версія** | Плаваюча (`@latest`) — у навчальному репо це прийнятно; у проді варто зафіксувати конкретну версію |

**Які tools він дав агенту:** `read_file`, `read_multiple_files`, `write_file`, `edit_file`, `create_directory`, `list_directory`, `directory_tree`, `move_file`, `search_files`, `get_file_info`, `list_allowed_directories`

**Перевірка, що працює:** попросив агента "покажи вміст app/data/catalog.json" — агент викликав `read_file` із правильним шляхом і повернув JSON із 24 товарами.

## Сервер 2 — memory

| | |
|---|---|
| **Навіщо** | Зберігає граф знань (entities та relations) у пам'яті між викликами. Корисний для збереження контексту при роботі з каталогом — наприклад, "запам'ятай, що ці SKU потребують замовлення" |
| **Транспорт** | stdio |
| **Як запускається** | `npx -y @anthropic-ai/mcp-memory@latest` |
| **Область доступу (scope)** | Не має доступу до файлової системи. Працює лише з власним in-memory графом знань. Дані зберігаються у файл `memory.json` у поточному каталозі |
| **Секрети** | Немає |
| **Версія** | Плаваюча (`@latest`) — прийнятно для навчального проєкту |

**Які tools він дав агенту:** `create_entities`, `create_relations`, `add_observations`, `delete_entities`, `delete_observations`, `delete_relations`, `read_graph`, `search_nodes`, `open_nodes`

**Перевірка, що працює:** попросив агента "створи сутність 'catalog' з описом '24 synthetic products'" — агент викликав `create_entities` і підтвердив створення.

## Що НЕ підключали і чому

- **git** (`uvx mcp-server-git`) — потребує Python та `uv`, яких немає в середовищі. Крім того, для задач домашки git-операції не потрібні через MCP — Claude Code вже має вбудовану підтримку git.
- **fetch** (`uvx mcp-server-fetch`) — потребує Python та `uv`. До того ж, сервер що тягне довільний контент з мережі, створює ризик prompt injection через зовнішні дані. Для read-only домашки з локальними даними мережевий доступ зайвий.

## Область доступу — головне

Filesystem-сервер обмежено виключно каталогом репозиторію (`/Users/iuade0tr/IdeaProjects/2026-udc-06-mcp-hw`). Аргумент зі шляхом — це fallback: якщо хост підтримує MCP Roots, сервер бере scope звідти. У stderr filesystem-сервера при відсутності підтримки Roots видно: `Client does not support MCP Roots, using allowed directories set from server args`. Варто пам'ятати, що `roots` за специфікацією — механізм координації, а не безпеки (сервер *SHOULD* їх поважати, не *MUST*), і вони позначені deprecated у ревізії 2026-07-28. Справжня межа безпеки — це права ОС або пісочниця.
