# A/B-валідація MCP (Task D)

**Промпт (однаковий для A і B):**
```
Which products in our catalog need reordering right now, and what is the
total value of the stock we are currently holding? Give me the SKUs and
the total as a number.
```

**Хост / модель:** Claude Code (CLI) / Opus 4.6
**Сервер під тестом:** `mcp-server/` (tools: `search_inventory`, `low_stock`; resource: `inventory://catalog`)

## Ground truth

Порахований локально командою з `materials/ab-question.md`:

```bash
cd app && npm run build
node -e "import('./dist/index.js').then(m=>{const c=m.loadCatalog();console.log(m.lowStock(c).map(p=>p.sku).join(', '));console.log(m.inventoryValue(c));})"
```

```
SKU, що потребують дозамовлення: DK-4001, WC-8002, DS-6002, MS-2001, MN-3002, HS-5002, SS-1102, KB-1002, CB-7003
Загальна вартість запасів: 46152
```

9 товарів із `stock <= reorderLevel`, відсортовані за зростанням stock. Загальна вартість — `sum(price * stock)` по всіх 24 товарах = $46 152.00.

## Прогін A — MCP підключено

**Що зробив агент:** агент побачив доступні tools від catalog-server і викликав `low_stock` (без аргументів). Tool повернув список 9 SKU з поточним stock і reorder level. Далі агент прочитав resource `inventory://catalog`, який містив загальну вартість запасів ($46 152.00). Агент не потребував додаткових кроків — два виклики дали повну відповідь.

**Відповідь:**
- SKU для дозамовлення: DK-4001, WC-8002, DS-6002, MS-2001, MN-3002, HS-5002, SS-1102, KB-1002, CB-7003 (9 штук)
- Загальна вартість запасів: $46 152

**Правильно?** Так — і список SKU, і загальна сума збігаються з ground truth.

## Прогін B — MCP вимкнено

**Як саме вимикали:** видалено секцію `"catalog"` із `.mcp.json` і перезапущено хост (нова сесія Claude Code), щоб старі tools не залишались у кеші.

**Що зробив агент:** без MCP-серверу агент використав вбудовані можливості Claude Code — прочитав `app/data/catalog.json` безпосередньо через вбудований Read tool. Потім вручну проаналізував JSON: відфільтрував товари з `stock <= reorderLevel` і обчислив `sum(price * stock)`. Агент виконав кілька кроків: спершу прочитав файл, потім написав і запустив Node.js скрипт для підрахунку, щоб не помилитися в арифметиці.

**Відповідь:**
- SKU для дозамовлення: DK-4001, WC-8002, DS-6002, MS-2001, MN-3002, HS-5002, SS-1102, KB-1002, CB-7003 (9 штук)
- Загальна вартість запасів: $46 152

**Правильно?** Так — агент дістався правильної відповіді і без MCP-сервера.

## Таблиця відмінностей

| Аспект | A (з MCP) | B (без MCP) |
|---|---|---|
| Викликав tool | Так — `low_stock` + resource `inventory://catalog` | Ні — прочитав JSON напряму (Read) і запустив скрипт (Bash) |
| Список SKU повний | Так, 9/9 | Так, 9/9 |
| Загальна сума точна | Так, $46 152 | Так, $46 152 |
| Скільки кроків знадобилось | 2 (tool call + resource read) | 3–4 (read file + write script + run script + parse output) |
| Впевненість відповіді vs її правильність | Висока впевненість, правильна відповідь — tool дає структуровані дані | Висока впевненість, правильна відповідь — агент перевірив себе скриптом |

## Висновок

MCP-сервер не змінив кінцевий результат — обидва прогони дали правильну відповідь. Це чесний нульовий результат. Claude Code і без MCP-сервера має достатньо інструментів (Read, Bash), щоб прочитати JSON і виконати обчислення. Різниця — в ефективності: з MCP агент отримав відповідь за 2 виклики зі структурованими даними, а без MCP — мусив сам знайти файл, прочитати його, написати скрипт і виконати його. MCP-сервер варто підключати, коли: (1) дані не лежать у відкритому файлі, а за API чи в базі; (2) бізнес-логіка складніша і її не варто переписувати в ad-hoc скрипті; (3) агент не має прямого доступу до файлової системи (наприклад, у веб-чаті Claude). У нашому випадку, де дані — це простий JSON у репо, а хост має повний доступ до файлів, MCP-сервер дає зручність, але не є необхідним.
